# ADR 003 — Local embeddings with Ollama

**Status:** accepted · 2026-11-19

## Context

Search by meaning needs embeddings. The original project uses Workers AI with
`bge-m3` (1024 dimensions), billed by neurons. I need a local equivalent.

## Decision

Embeddings are generated by Ollama running on `127.0.0.1:11434`, with `bge-m3`
as the default model.

The model is configurable. The dimension is **not** configured: it comes from
the first vector generated and is stored in the index.

## Alternatives considered

**External API (OpenAI, Voyage, Cohere).** Rejected. Embedding quality would be
better, but it sends the content of my notes off the machine, costs per use and
breaks when the machine is offline. For personal notes, the quality gain does
not pay those three prices.

**The Smart Connections Obsidian plugin.** Rejected. I would consume the
plugin's index instead of building my own. Less code, but the index format is a
third party's decision and may change without notice, and I would lose control
over chunking and over hybrid search.

**sentence-transformers in process.** Rejected. It would bring PyTorch in as a
dependency, which is far too heavy for a CLI that has to start fast. Ollama
keeps the model loaded between calls, which keeps the CLI light.

## Consequences

- Zero cost and no data leaving the machine.
- Ollama becomes a prerequisite. The CLI must detect that it is not running or
  that the model has not been pulled, and say so plainly instead of surfacing a
  raw connection error.
- `bge-m3` is multilingual, which matters because my notes mix Portuguese,
  English and code snippets.
- Changing the model invalidates the index, because the dimension and the
  vector space change. The index stores the dimension and refuses to operate
  with an incompatible model, asking for `--rebuild`.
- Vectors are normalised to unit length at the embedder's output. Euclidean
  distance then orders results the same way as cosine, and I do not depend on
  the vector extension accepting `distance_metric=cosine`.
